# copper-cloud v0.7.0

An org-wide budget for Copper's agent: how many rounds of tool calls the agent pane may run for
one question, set once by the admin for everyone on the instance. Additive only: 0.6 clients
keep working unchanged.

### Agent round budget

- **One setting, whole org.** `agent.max_turns` is an integer from 1 to 500 (or unset). Copper
  uses it instead of each person's local setting while it is set; unset means everyone keeps
  their own (Copper's default is 60).
- **Served regardless of key sharing.** `GET /v1/intelligence` gains a fourth field,
  `"agent": {"max_turns": N} | null`, present even when sharing is off or no keys are stored —
  it is a limit, not a key. Older Coppers ignore it; an absent field (older servers) means "no
  org value".
- **Admin API.** `GET /admin/api/intelligence` adds `agent` and `defaults.agent_max_turns`
  (60). `PUT` takes `"agent"` with the same rules as the key blocks: missing = unchanged,
  `null` = clear, `{"max_turns": N}` = set; anything out of range or not an integer → `400`.
  Changes are audited (`intelligence.update` with `agent` in the detail). `DELETE` still
  removes only the keys; the budget stays.
- **CLI.** `copper-cloud intelligence set --agent-max-turns N`, `copper-cloud intelligence
  clear --agent`; `show` prints the value. A plain `clear` keeps the budget.
- **Portal.** AI keys › **Agent**: "Tool-call rounds per question (whole org)", Save / Clear.
  Blank = each person's own Copper setting.
- **Storage.** Migration `0011_intelligence_agent` adds a nullable `agent_max_turns` column
  (CHECK 1–500) to the `intelligence_settings` singleton row. Plaintext; not secret.
