# copper-cloud v0.4.0

Cloud-wide intelligence keys. An instance admin sets one Jev (TypeSafe) key — with its endpoint
and model — and one LLM router (LiteLLM) key with its base URL, and every signed-in Copper picks
them up from the new `GET /v1/intelligence` endpoint, so nobody on the cloud pastes a key by hand.

- **Users:** `GET /v1/intelligence` (gate credential + session) returns
  `{"jev": {key, endpoint, model} | null, "router": {key, url} | null, "updated_at": RFC3339 | null}`;
  nulls when unset or when the admin turns sharing off.
- **Admins:** a new **AI keys** page in the portal and `GET/PUT/DELETE /admin/api/intelligence`
  (write-only keys: only the last four characters are ever shown; partial updates keep the stored
  key; a sharing toggle withholds keys without deleting them).
- **Shell:** `copper-cloud intelligence set --jev-key-file F --router-key-file F [--router-url U]
  [--jev-endpoint U] [--jev-model M]`, `show` (masked), `clear [--jev|--router]`,
  `enable` / `disable`. Keys come from files or stdin, never argv.
- **Security:** keys are envelope-encrypted under the master key (migration `0010`), never logged,
  and every change plus user reads (once per user per hour) land in the admin audit log.

Upgrade in place with the release tarball's `install.sh` (keeps config, keys, certificate and link
codes; applies the migration).
