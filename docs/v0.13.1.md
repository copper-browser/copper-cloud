# copper-cloud v0.13.1

Fixes in the device agent relay ([api.md](api.md#device-agent-relay)). No new migrations, no API
removed: an upgrade from 0.13.0 is a binary swap (`sudo ./install.sh` from the tarball), and a
rollback to 0.13.0 is too.

- **A dropped stream no longer loses a call.** A request sent down a stream that died before the
  phone answered waited out the whole 200 s deadline. Now every stream the phone opens gets the
  requests still pending on its link again, right after `hello` (same id, `deadline_ms` = the
  time left), and a call stays pending until a new stream re-delivers it or the phone has been
  offline for 15 s. The phone answers a request it already answered with its stored reply.
- **At most 8 calls in flight per phone.** One more answers at once with `isError: true`:
  "Copper on <device> is busy with other calls; try again shortly." (status `busy`).
- **An agent that does not read its answer holds nothing up.** Each call now waits in a task of
  its own: it ends at its deadline (and on cancel, revoke or shutdown) whether or not the agent
  reads its SSE answer, a slow reader loses progress notifications beyond 32 buffered (never the
  response), and a frames POST never waits on any agent.
- **Disabling or deleting a user stops their agents' calls.** From the admin API, their phones'
  streams close with `revoked`, their calls in flight fail (status `user_revoked`) and their
  rate-limit state is dropped at once; `copper-cloud admin disable-user` / `delete-user` (which
  work on the database) reach a running server within 10 s.
