# copper-cloud v0.10.0

Addons: small web bundles that replace a slot of the Copper window, uploaded once and handed
out by the cloud. Additive only: 0.9 clients keep working unchanged and simply ignore them.

- **Addons.** An addon is a `.copperaddon` zip (`manifest.json` with schema
  `copper-addon/1`, plus HTML, JavaScript, CSS and assets) written for one **slot**. The slot
  list is closed; v1 has `agent-sidebar`, the pane toggled by ⌘E on the Mac and Ctrl+E on
  Linux and Windows. See [addons.md](addons.md).
  - Uploads are validated: the manifest schema, the slot, size caps
    (`limits.max_addon_bytes`, default 16 MiB), and path rules. Zip traversal and zip
    bombs are refused, and only Deflate and Stored entries are accepted.
  - Each version is stored as a canonical served bundle (`copper-addon-bundle/1`). Its
    SHA-256 is the version's identity, and every Copper verifies it before running anything.
  - **Off by default.** An upload reaches nobody until an admin turns it on for everyone or
    for listed people (emails, case-insensitive).
  - Settings are typed by the manifest. The admin's values are validated, merged over the
    manifest's defaults and served with the addon.
- **Client API.**
  - `GET /v1/addons` returns the addons that apply to the signed-in person, with their
    resolved settings and a revision. It answers 304 to `If-None-Match`.
  - `GET /v1/addons/{id}/bundle/{sha256}` serves only versions handed to that person.
  - `addons` is added to `/v1/info` `features`.
  - An `addons` event on the event stream tells connected Coppers to look again.
- **Admin API.** Under `/admin/api/addons`:
  - `GET …/slots`, `GET` (list), `GET …/{id}`;
  - `POST ?slot=…` (raw zip upload);
  - `PATCH …/{id}` (`enabled`, `audience`, `people`, `settings`, `priority`,
    `current_version`);
  - `DELETE …/{id}`, `GET …/{id}/versions/{version}/bundle`.

  Every route needs an admin session, and every change is audited (`addon.create`,
  `addon.upload`, `addon.update`, `addon.delete`; setting values are never logged).
- **CLI.** `copper-cloud addons list|slots|upload|enable|disable|settings|delete`, also
  reachable as `copper-cloud admin addons …`.
- **Portal.**
  - An **Addons** page: addons grouped by slot, on/off, an audience picker, a settings form
    generated from the manifest, versions and upload.
  - A public **/download/** page that detects the visitor's OS. A link code is carried only
    in the URL fragment, so it never reaches the server.
  - **Copy download link** on a newly minted access key.
- **Migration** `0014_addons` adds the tables `addons`, `addon_versions` (bundles as
  `bytea`) and `addon_audience`.

Clients: Copper for Linux 0.4.0 and Copper for macOS (next release) show addons in the
Agent sidebar. Copper for Windows mounts the same slot.
