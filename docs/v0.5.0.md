# copper-cloud v0.5.0

Invites you can see, re-send and take back, and history sync that can no longer wedge on one
bad entry. Additive only: 0.4 clients keep working unchanged.

- **Re-send reminds the invitee.** `POST /v1/canvases/{id}/invites` for an email that already
  has a pending invite still answers `200` with that invite, but now also reminds the invitee:
  at most once per 30 s per invite it stamps `nudged_at` and sends them a `canvas` event
  (kind `invited`) so their Copper surfaces the invite again. The response says whether it
  did (`"nudged": true|false`). Before, a re-send did nothing at all.
- **Invite views say more.** Every invite (`GET /v1/canvases/{id}/invites`, `GET /v1/invites`,
  `POST` responses) gains `invitee` (`{id, email, display_name}` of the account with that
  email, or `null` while nobody has signed up with it) and `nudged_at` (RFC 3339 or `null`).
- **Revoke.** `DELETE /v1/canvases/{id}/invites/{invite_id}` → `204`, for the canvas owner or
  the member who sent the invite (`403` for other members, `404` when unknown or no longer
  pending). The invite becomes `revoked`, disappears from both lists, and the invitee gets a
  `canvas` event with kind `invite_revoked`.
- **History: per-entry problems no longer fail the batch.** `POST /v1/sync/history` used to
  answer `400` for the whole batch when one entry was too large (> `max_history_entry_bytes`),
  not an object, or had an unreadable `visited_at` — and a client that resends the same batch
  (Copper does) was stuck on it forever. Such entries are now skipped and listed in the `200`
  response (`"rejected": [{"index", "reason", "message"}]`) while the rest is stored, so an
  already-installed Copper recovers on its next retry after the upgrade, with no client
  update. Invalid UTF-8 inside an entry is repaired instead of failing the request.
  Whole-request problems (not JSON, no `entries` array, more than `max_history_batch`
  entries) are still `400`, with a message that says which.
- **Diagnosable errors.** The per-request log line now carries `error` (the error code the
  client got) and, for `400`s, `error_message` (the client-facing message, quoted input values
  redacted). New counter `history_rejected`.

Migration `0102_canvas_invite_nudge` adds `canvas_invites.nudged_at` and the `revoked` status.
Upgrade in place with the release tarball's `install.sh` (keeps config, keys, certificate and
link codes; applies the migration).
