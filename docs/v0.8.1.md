# copper-cloud v0.8.1

Public source release. No API, schema or client-visible changes beyond the router URL default
below; 0.8.0 clients and instances keep working unchanged.

- **No built-in LLM router URL.** Earlier builds filled a missing router URL with a
  deployment-specific gateway. Now a new router block needs an explicit URL — admin API
  `PUT /admin/api/intelligence` with `{"router": {"key": …, "url": …}}`, the portal's
  *Router URL* field, or `copper-cloud intelligence set --router-key-file F --router-url U` —
  and a key without one is a `400 bad_request`. `defaults.router_url` is gone from the admin
  settings object.
- **Existing settings are preserved.** The router URL an instance already stores (in
  `intelligence_settings`) is untouched by the upgrade, kept across key rotations and sharing
  toggles, and still served by `GET /v1/intelligence`. Nothing to migrate.
- **Docs and examples are generic.** Deployment-specific hosts, accounts and the internal
  onboarding page were replaced by placeholders (`example.com`, `demo`) and a generic
  [team onboarding guide](onboarding.md).
- **License.** MIT, now with a [`LICENSE`](../LICENSE) file that also ships in the release
  tarball; crate metadata names the repository and license.

No migration. Upgrade in place with the release tarball's `install.sh`.
