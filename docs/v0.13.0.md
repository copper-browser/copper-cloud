# copper-cloud v0.13.0

Agents can use a person's Copper for iOS through the cloud. One new migration
(`0016_device_agent`); an upgrade from 0.12.x is a binary swap (`sudo ./install.sh` from the
tarball) and the server migrates on start.

- **Device agent relay** ([api.md](api.md#device-agent-relay)). Copper for iOS registers a link
  with its tool manifest (`POST /v1/me/links`) and, while Copper is on screen and the person has
  turned agents on, holds an event stream (`GET /v1/me/links/{id}/frames`). An agent — phi,
  Claude Code, any MCP client — calls `POST /v1/agent/mcp` with a `cat_` token the phone minted
  (`POST /v1/me/agent-tokens`); the cloud hands each `tools/call` to the phone and returns its
  reply, as JSON or as an SSE stream with keepalives and progress notifications. A deadline miss
  or an agent that goes away sends the phone a `cancel`; a phone that is not open is answered at
  once. `/v1/info` lists `device_agent`.
- **`/v1/agent/*` is outside the instance gate**: the 256-bit token is the credential (only its
  SHA-256 is stored), limited to 600 requests a minute per token. Revoking a token, the link, or
  deleting the device stops calls at once.
- **Logs and metrics.** One `agent call` line per call (token id, device id, tool, duration,
  outcome; never arguments or results), and `device_agent_streams`, `device_agent_calls_total`,
  `agent_rate_limited_total`.

Agents need a certificate their HTTP client trusts: ACME (or a TLS-terminating proxy) works as
is; a self-signed instance's certificate must be trusted explicitly.

## Rollback

0.12.x does not know migration `0016`, and sqlx refuses a database with an applied migration it
does not know: 0.12.x `serve`, `migrate` and its installer stop with "migration 16 was
previously applied but is missing in the resolved migrations". `0016` only adds two tables, so
either run 0.12.x as `copper-cloud serve --no-migrate`, or remove the migration first (as the
`postgres` superuser or the database owner; every device link and agent token is lost, nothing
else is touched) and reinstall the previous release:

```sh
sudo systemctl stop copper-cloud
sudo -u postgres psql -w -d copper_cloud -v ON_ERROR_STOP=1 -c \
  "BEGIN; DROP TABLE agent_tokens; DROP TABLE device_links; DELETE FROM _sqlx_migrations WHERE version = 16; COMMIT;"
tar xzf copper-cloud-0.12.0-linux-$(uname -m).tar.gz && sudo ./install.sh
```

Upgrading again later re-applies `0016` cleanly (phones register their links again; agent
tokens must be minted again).
