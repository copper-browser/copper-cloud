# copper-cloud v0.12.0

Sync documents can be put back. One new migration (`0015_sync_doc_revisions`); an upgrade from
0.11.x is a binary swap (`sudo ./install.sh` from the tarball) and the server migrates on start.

- **Revisions of every sync document** ([api.md](api.md)). Before a `spaces`, `settings`,
  `bookmarks` or `tabs:<device>` document is overwritten, the version it replaces is kept
  (still encrypted) with the device that wrote it and its build. The last 20 per document are
  kept. `GET /v1/sync/docs/{domain}/revisions` lists them, `GET …/revisions/{version}` returns
  one, and `POST …/revisions/{version}/restore` writes it back as a new version, so every
  device pulls it. `/v1/info` lists `doc_revisions`.
- **`X-Copper-Build`.** Coppers may send their build with a write; it is stored beside the
  document and its revisions. Optional: older Coppers sync as before.
- **`copper-cloud admin docs revisions|restore --user --domain [--version]`** for the operator.

Why: a device whose state had drifted overwrote a user's folders on every Mac, and there was no
earlier version to go back to (Copper 1.0.20261029.95, copper-linux 0.5.1 and copper-windows
0.2.1 stop the overwrite itself).
