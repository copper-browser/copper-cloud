# copper-cloud v0.11.1

Canvases in any browser. Additive: Coppers, the canvas API and the database are unchanged (no new
migrations), so an upgrade from 0.11.0 is a binary swap (`sudo ./install.sh` from the tarball).

- **Canvas App at `/canvas/`** ([canvas.md › Canvas App](canvas.md#canvas-app-canvas)).
  `GET /canvas/` serves [Canvas App](https://github.com/copper-browser/canvas-app), the canvas in
  any browser, for people who are not on Copper. It is one self-contained page vendored as
  `crates/copper-cloud/assets/canvas-app.html` (`packaging/sync-canvas-app.sh` updates it). The
  route is ungated and holds no data; it sends `Cache-Control: no-cache`, `nosniff`,
  `Referrer-Policy: no-referrer` and CSP `frame-ancestors 'none'`, and `/canvas` redirects (308)
  to `/canvas/`. The app reaches the linked Canvas Cloud through the same proxy Copper uses, on
  the server's own origin, so no CORS is involved.
- **`?instance=` on the canvas room socket.** A browser cannot set headers on a WebSocket, so the
  gate also accepts the instance credential as `?instance=` on `/v1/canvases/{id}/ws` upgrades
  (only there). Query strings are never logged, and the canvas link strips `instance=` (like
  `token=`) before forwarding, so Canvas Cloud never sees it.
- **Share links** (`/join/{token}`) offer Canvas App (`/canvas/#/join/{token}`) under the Copper
  button.
