# copper-cloud v0.11.0

Canvases move out of copper-cloud into a linked [Canvas Cloud](https://github.com/copper-browser/canvas-cloud),
a standalone, self-hostable canvas server. Coppers need no update: copper-cloud keeps serving the
same canvas API and proxies it, as the signed-in person, to the Canvas Cloud it is linked to.

**Upgrading an instance that has canvases** (any earlier release): follow the runbook in
[canvas-migration.md](canvas-migration.md) — install Canvas Cloud, link it, run
`copper-cloud canvas migrate`, then start the server. Until a Canvas Cloud is linked, canvas routes
answer `503 canvas_unavailable` and everything else (sync, SSO, addons, intelligence) works as before.

- **Canvas link** ([canvas-link.md](canvas-link.md)).
  - `/v1/canvases…`, `/v1/people`, `/v1/invites…`, `/v1/canvas-links/…`, `/v1/mentions…` and the
    y-websocket room are proxied to Canvas Cloud with the link's app key and the caller's user id.
    Request and response bodies, close codes and SSE `canvas` events are unchanged.
  - People are provisioned on Canvas Cloud on first use, by a background reconcile and through an
    outbox for changes (rename, disable, delete). The reconcile never deletes; `canvas sync-users
    --prune` does, explicitly.
  - Canvas Cloud's events are bridged into `/v1/sync/events` (`event: canvas`), resuming after
    restarts on either side.
  - Errors: `502 canvas_upstream` when Canvas Cloud is unreachable or refuses the key (a Canvas
    Cloud 401 is never forwarded, so nobody is signed out), `503 canvas_unavailable` when unlinked.
    Room sockets get a 30 s keepalive and close `1011` when the upstream connection is lost.
  - `/v1/info`: `canvas_link` in `features` and `canvas: {linked}`.
- **Migration** ([canvas-migration.md](canvas-migration.md)). `copper-cloud canvas migrate
  [--dry-run] [--only ID]… [--replace] [--concurrency N] [--json]` copies every legacy canvas — ids,
  members and roles, full update history, invites, share links (their tokens keep working), mentions
  — into Canvas Cloud and verifies each by document digest. It is idempotent and resumable. The
  legacy tables are left untouched, so a rollback to 0.10.0 is possible (documented).
- **Removed:** the built-in canvas engine (`crates/canvas`). It lives on, with its history, in
  Canvas Cloud.
- **CLI:** `copper-cloud canvas link|unlink|status|sync-users|migrate`; `doctor` checks the link.
- **Admin API + portal:** a **Canvas Cloud** page (link, test, unlink, provision users); Canvases and
  Overview show an unlinked state.
- **Migration** `0030_canvas_link` adds `canvas_link` and the provisioning outbox.
